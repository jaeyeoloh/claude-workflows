# /new-project

새 프로젝트(플랫폼, 외주, 웹사이트 등) 시작 시 표준 워크플로우를 실행합니다.

## 실행 흐름

$ARGUMENTS 에 프로젝트 설명이 있으면 사용하고, 없으면 아래 질문을 순서대로 진행한다.

### Step 1 — 프로젝트 성격 파악
다음을 확인한다:
- 핵심 목적 (어떤 문제를 푸는가)
- 프로젝트 유형: 플랫폼(marketplace/community) / 외주(클라이언트 요청) / 내부 도구 / 기타
- 타겟 사용자 (한국 사용자? 글로벌?)

### Step 2 — 시작 단계 결정
- 기획/설계 먼저 vs 바로 개발
- 외주라면: 클라이언트 요구사항 명세서 존재 여부 확인

### Step 3 — 기술 스택 결정
프로젝트 성격에 따라 아래 중 추천:
- **빠른 MVP/외주**: Next.js + Supabase (풀스택, 인증/DB 포함)
- **확장 가능한 플랫폼**: React + Node.js + PostgreSQL (분리 아키텍처)
- **정적 사이트/랜딩**: Astro or Vite + React
- **한국 서비스**: 카카오 OAuth + 토스페이먼츠 고려 필수

### Step 4 — 표준 파일 생성
1. `docs/PRD.md` 생성 (타겟 유저, 핵심 기능, 완료 기준, Out of Scope)
2. `docs/workflow-log.md` 생성 (DEC-001부터 결정 기록 시작)
3. `CLAUDE.md` 생성 (프로젝트 컨텍스트 및 스택 정보)
4. 선택한 스택으로 프로젝트 스캐폴드 생성

### Step 5 — MVP 범위 합의
- 반드시 코딩 전에 MVP 기능 목록 확정
- Wave 1 (론칭) / Wave 2 (검증 후) 로 구분
- 각 기능마다 완료 기준 명시

### Step 6 — 구현 시작
DB 스키마 → 인증 → 핵심 기능 순서로 진행
